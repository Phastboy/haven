# Haven Roadmap 0.5: Search and Price Filtering Design & Implementation

## 1. Overview & Objective

Roadmap 0.5 addresses the core product question:
> **"Can I find the offer I'm looking for?"**

Before this stage, visitors had to encounter offers by chance or know a maker's direct handle. In Roadmap 0.5, a person can deliberately find an offer by searching its title and narrowing down offers by price and currency.

---

## 2. Product Journeys

1. **Offerer Lane:**
   - Maker creates an offer with title, description, price (or 0 for Free), currency, and photos.
   - The offer is indexed for full-text search and price filtering as soon as at least one photo is attached (`image_count >= 1`).
2. **Responder / Discovery Lane:**
   - Visitor navigates to `/offers`.
   - Searches for keywords in offer titles via the search box.
   - Optionally selects a currency and specifies a minimum and/or maximum price.
   - Specifying `max_price = 0` narrows the feed to Free offers.
   - Paginates through results with all active filters preserved across "Next →" / "← Previous" links.
   - If no offers match the search criteria, a clear empty state explains that no offers matched, offering a single-click action to "Clear all filters".

## 3. Database Schema & Indexing (Migration 015)

### Tradeoff Analysis: Full-Text Search (`tsvector`) vs `pg_trgm`

- **Extension Availability:** `pg_trgm` availability on hosted cloud databases (e.g., Neon, Koyeb, AWS RDS) is not guaranteed and requires extension privileges.
- **Query Performance:** PostgreSQL's built-in `tsvector` with a stored generated column and GIN index delivers sub-millisecond query execution on large datasets without external extensions.
- **Decision:** Use PostgreSQL's built-in `to_tsvector('english', title)` with a generated column and GIN index.

### Schema Additions

```sql
-- Migration 015: Offer title search and price narrowing indexes

ALTER TABLE offer
    ADD COLUMN IF NOT EXISTS title_search tsvector
    GENERATED ALWAYS AS (to_tsvector('english', title)) STORED;

-- Partial GIN index for full-text title search (matches public visibility rule)
CREATE INDEX IF NOT EXISTS idx_offer_title_search
    ON offer USING gin (title_search)
    WHERE image_count >= 1;

-- Partial B-Tree index for currency and price range filtering with keyset ordering
CREATE INDEX IF NOT EXISTS idx_offer_feed_currency_price
    ON offer (currency, price, created_at DESC, id DESC)
    WHERE image_count >= 1;
```

Both indexes are **partial on `image_count >= 1`**, preventing index bloat from unpublished drafts or offers without cover images.

## 4. Performance Benchmarks (`EXPLAIN ANALYZE` on 120,196 Seeded Offers)

On a live PostgreSQL database containing **120,196 offers**:

### Title Search Query
```sql
EXPLAIN ANALYZE
SELECT o.id, o.user_id, o.slug, o.title, o.description, o.price, o.currency, o.image_count, o.created_at, o.updated_at,
       u.display_name, u.handle
FROM offer o
JOIN "user" u ON o.user_id = u.id
WHERE o.image_count >= 1
  AND o.title_search @@ plainto_tsquery('english', 'Wooden')
ORDER BY o.created_at DESC, o.id DESC
LIMIT 20;
```
- **Execution Plan:** Bitmap Index Scan on `idx_offer_title_search` -> Bitmap Heap Scan -> Sort -> Limit.
- **Execution Time:** **0.901 ms** (sub-millisecond).

### Price & Currency Range Query
```sql
EXPLAIN ANALYZE
SELECT o.id, o.user_id, o.slug, o.title, o.description, o.price, o.currency, o.image_count, o.created_at, o.updated_at,
       u.display_name, u.handle
FROM offer o
JOIN "user" u ON o.user_id = u.id
WHERE o.image_count >= 1
  AND o.currency = 'NGN'
  AND o.price >= 1000
  AND o.price <= 50000
ORDER BY o.created_at DESC, o.id DESC
LIMIT 20;
```
- **Execution Plan:** Index Scan using `idx_offer_feed_currency_price` (or `idx_offer_feed_visible` depending on selectivity / sort cost tradeoff) with user join memoization.
- **Execution Time:** **4.158 ms**.

## 5. Domain Modeling (`haven-domain`)

- **`SearchQuery`**: Validated value type (1 to 100 characters; whitespace trimmed). Blank queries or queries exceeding 100 characters produce explicit `FilterValidationError` values.
- **`PriceFilter`**: Paired strictly with an ISO 4217 `CurrencyCode`. Contains optional `min: Option<Price>` and `max: Option<Price>`. `0` minor units represents a Free offer. Enforces `min <= max`.
- **`OfferFilter`**: Aggregate filter containing optional `title` and `price`.
- **`PublicFeedQuery`**: Encapsulates `filter: OfferFilter`, `cursor: Option<OfferCursor>`, and `limit: usize` (clamped to 50 max) into a single struct, keeping function arguments $\le 3$.

## 6. Web UI & Component Architecture (`haven-web`)

- **Component:** [`feed_filters.rs`](../expts/rust/crates/haven-web/src/app/components/feed_filters.rs)
  - Designed in Haven's calm, text-led, greyscale aesthetic.
  - Search field (`#filter-q`) and price filter grouping (`#filter-currency`, `#filter-min-price`, `#filter-max-price`).
  - Validation errors render inline with accessible `role="alert"` tags.
- **Keyset Pagination Preservation:**
  - When paginating, the query serializer appends `q`, `currency`, `min_price`, and `max_price` alongside the `after` cursor, ensuring that active filters survive pagination navigation without resetting.
- **Dual Empty States:**
  - *Unfiltered empty feed:* "No offers available yet" + "Create an Offer" action.
  - *Filtered empty feed:* "No offers match your filters" + "Clear all filters" action resetting to `/offers`.
